## 🟤 Phase 6 — Verify against acceptance criteria (goal-backward)

- **Prose quality (same model pass):** Before saving or reviewing decision-bearing prose, read all of `${CLAUDE_PLUGIN_ROOT:-$CLAUDE_SKILL_DIR}/references/workflow-prose-quality.md` (Codex: `$KIMIFLOW_PLUGIN_ROOT/references/workflow-prose-quality.md`) and apply it before output; add no agent, call, step, or gate.

Run each check, prove the goal, and persist full evidence in the run artifacts — full checklist (incl. the ✓/⚠/✗ marking scheme, cold-start trigger list, LSP tool selection): → reference.md "Verification". If resolved verbosity is `quiet`, chat shows only pass/fail + command/path for decisive checks; full output stays in files.

- **Pi visible-Ship handoff.** After every required mechanical check is green, a FirstMate implementation Ship follows Phase 5's bounded review-checkpoint rule, reports `paused` with the exact commit, and stops. Kimiflow Main—not Captain or the Ship—then dispatches the scheduled visible review Scouts. A failed check loops to Phase 5 before any review handoff.

- **Run each criterion's method** and show the command + the decisive result line(s) — not full logs. At `quiet`, show only the command label/status and artifact path unless a failure needs the decisive error line.
- If the decisive method requires a clean tree, enter only through Phase 5's named local verification checkpoint and run it immediately; its failure loops to Phase 5 without user interaction.
- **Goal-backward:** for each criterion's artifact check Exists / Substantive / Wired — "task done ≠ goal achieved".
- **Fix mode (mandatory):** the reproduction no longer fails. Then run `${CLAUDE_PLUGIN_ROOT:-$CLAUDE_SKILL_DIR}/hooks/red-green-gate.sh .kimiflow/<slug> --mode fix` (Codex: `KIMIFLOW_HOST=codex` and `KIMIFLOW_PLUGIN_ROOT`). `OPEN` is required before Phase 7, memory promotion, or `Status: done`.
- **Local diagnostics advisory:** when code changed, run `${CLAUDE_PLUGIN_ROOT:-$CLAUDE_SKILL_DIR}/hooks/lsp-diagnostics.sh` and append any `FLAG` lines to `.kimiflow/<slug>/ADVISORIES.md` (bounded existing local tools only, never installs).
- **Regression:** existing/affected test suite green.
- **Reusable release evidence (ready schema-v2 profile only):** when an adopted project release profile marks the exact unauthenticated Phase-6 command with `auth=none` and `reuse=kimiflow_verification`, execute that criterion through `${CLAUDE_PLUGIN_ROOT:-$CLAUDE_SKILL_DIR}/hooks/release-profile.sh evidence-execute --run .kimiflow/<slug> --check <id> --input <name=value>... --write` (Codex: `$KIMIFLOW_PLUGIN_ROOT/hooks/release-profile.sh`) instead of running the same command a second time. Provider-authenticated checks are never reusable because their result depends on the ephemeral release identity. The mechanical command captures content-free evidence under the release runtime's sealed environment; it adds no model call. Missing inputs, a nonmatching check, failed execution, terminal Verification/Conformance failure, HEAD/path/env/PATH/tool drift, or any effect disables reuse and leaves the normal release execution mandatory.
- **Architecture falsification (when active):** execute the PLAN's `Architecture check`, then compare the delivered diff and real integration/data-flow evidence with the recorded operating envelope and `fit|evolve|replace` decision. Under Conformance Contract 1, a failed falsifier or disproved invariant is `architecture_falsified` and returns to Phase 2 with changed evidence/strategy; legacy runs return to Phase 5. Unsupported reviewer taste does not steer either route.
- **Frontend contract (when declared).** Recompute the full Active-Run Git delta (committed, staged, unstaged, untracked, deletes and both rename sides), make STATE `Affected files` set-equal, recheck Lane/evidence, then run `${CLAUDE_PLUGIN_ROOT:-$CLAUDE_SKILL_DIR}/hooks/frontend-quality-gate.sh .kimiflow/<slug> --record-routing --write` (Codex: `$KIMIFLOW_PLUGIN_ROOT/hooks/frontend-quality-gate.sh`). If routing reveals a new UI signal, return to Phase 2/5. For `off`, create no visual artifact and require the normal gate OPEN. For `standard|flagship`, read all of `${CLAUDE_PLUGIN_ROOT:-$CLAUDE_SKILL_DIR}/references/frontend-quality-qa.md` (Codex: `$KIMIFLOW_PLUGIN_ROOT/references/frontend-quality-qa.md`), verify/correct the rendered implementation, write its exact `DESIGN-QA.md` plus current viewport-exact run-local PNG, then run the normal gate with `--write`. `Kind: contract` repairs only the reported contract; `Kind: visual` keeps screen identity fixed and changes strategy+pixels. CLOSED loops through Phase 5 without another user confirmation; OPEN alone advances.
- Cold-start smoke test when the diff touches boot-critical files; non-automatable criteria → a `top`/`cross_family_top` verifier subagent (derives pass/fail from evidence; does not trust the implementer's self-report). Mechanical commands and gates remain model-free.
- **(large) Evidence-routed semantic verifier:** resolve the exact model/variant/task/runtime/policy/prompt-gate key with `adaptive-control.sh review-resolve`, then reuse Phase 7's topology. An eval-proven `embedded` routine profile folds the goal-backward falsification into the implementer's single structured self-review and adds no verifier call; the shared deterministic audit sample, unproven/drifted profile, regression or repeated failure selects one implementer-blind `cross_family_top|top` verifier. Its existing packet includes the installed `workflow-prose-quality.md` path and same-pass/no-extra-call boundary. Pi Main with an active crew uses an ordinary visible FirstMate Scout when an independent verifier is required; a crewmate requests it through normal status and Pi without active crew folds the verifier locally. Critical security/data/migration/public-contract risk remains independent. A discrepancy never bounces the run by itself — re-run the decisive command: confirmed → phase 5, else record the rejected claim and proceed. Mechanical AC commands always run regardless of topology.
- **Implementation conformance (Contract 1 only; adaptive, not a new phase).** Recompute the complete Git delta from STATE `Run started head` (including tracked, staged, untracked, deletes, and both rename sides), make STATE `Affected files` set-equal, and execute every PLAN `Check Dn` exactly. In `VERIFICATION.md`, write one exact `Decision check Dn: passed :: <PLAN method>` and one `Evidence result Dn: <review_only|spike_required|runtime_required> :: passed|failed :: <current evidence>` per decision. Spike evidence must cite the exact current `SPIKE.md` digest; runtime evidence must come from the executed typed method; prose-only claims do not count. Contract-3 and Contract-4 features additionally write exactly one `Requirement Rn: passed :: <method/evidence>` row for every immutable INTENT requirement; missing, failed, duplicate, or unexpected rows close conformance. Classify the result as `converged|code_gap|strategy_drift|architecture_falsified|research_stale|scope_drift`; refresh current external sources only for a named staleness/dependency/falsifier signal. `small` and eval-proven embedded routine runs fold this judgment into the current orchestrator and make no extra model call; other `large` runs reuse the one scheduled verifier above. Keep exactly one conformance receipt, require the generic outcome receipt to pass, then record and reopen `conformance-gate.sh`. Non-converged results route mechanically to Phase 5 or Phase 2; the gate validates receipts/freshness and never executes PLAN commands.
- **Conditional architecture verification (schema 5).** For every active classifier selector, record exactly `Domain verification: passed; AC=AC-N` and/or `Operational verification: passed; AC=AC-N` in `VERIFICATION.md` after its named method passes. Record neither when off. Run `hooks/adaptive-control.sh contract --run .kimiflow/<slug> --stage verify`; only `OPEN` advances. This verifies project-specific invariants, signals, rollback and privacy evidence without an always-on architecture checklist.
- **Convergence verification (STATE `Convergence contract: 1`).** Before the broad conformance sweep, execute the exact slice checks and, for critical risk, every falsifier. Write exactly one `<!-- kimiflow:convergence-verification contract=1 risk=<routine|critical> slices=<N> failures=<M> -->`, then one `Slice check Sn: passed|failed :: command|verifier :: <exact PLAN payload>` per slice and one `Falsifier check Fn: passed|failed :: command|verifier :: <exact PLAN payload>` per declared failure class. - **Outcome receipt:** keep exactly one machine line in `VERIFICATION.md`: `<!-- kimiflow:verification outcome=<passed|failed> criteria=<passed|failed|not_run> regression=<passed|failed|not_run> -->`. Replace it after each verification attempt. `outcome=passed criteria=passed regression=passed` is allowed only after every required AC method and affected regression check is green; any other state stays failed/incomplete and cannot become a positive strategy outcome.
- **Recall attribution (when Contract 1 is present):** every applied `rec_<64>` must still exist in the current `RECALL.json` and be either linked by its `Recall Dn` to an exact `Decision check Dn` or bound by exact current contradiction evidence. A decision-changing counterexample uses `Recall Dn: none` plus `Recall contradiction <rec_id>: <repo-relative-path>:<positive-line>`; the regular non-symlink file and non-empty in-range line are validated and fingerprinted. `done` plus green Verification may classify a linked hit `helpful`; failed checks or valid counterevidence classify it `contradicted`; contradiction wins mixed signals. Missing Verification on `parked|aborted|failed` stays `neutral/inconclusive` and never creates another user stop, while malformed contracts remain fail-closed.
- **Execution evidence (Contract 1 only):** after `VERIFICATION.md` contains the decisive current attempt, record that artifact once with `active-run.sh observe --event verification --outcome passed|failed --evidence .kimiflow/<slug>/VERIFICATION.md --write`. Only its fingerprint enters the bounded journal. Re-running the command without new evidence does not manufacture progress.
- Any verification failure not classified by Contract 1 → back to Phase 5 (escalation rule applies); the Contract-1 Phase-2 drift routes above take precedence.
