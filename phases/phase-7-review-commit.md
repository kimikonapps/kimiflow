## 🟢 Phase 7 — Evidence-routed code review against specs → fix → commit-gate

0. **Frontend serialization preflight.** Before every Phase-7 entry/re-entry, run `${CLAUDE_PLUGIN_ROOT:-$CLAUDE_SKILL_DIR}/hooks/frontend-quality-gate.sh .kimiflow/<slug> --write` (Codex: `$KIMIFLOW_PLUGIN_ROOT/hooks/frontend-quality-gate.sh`). Contract 1 requires OPEN plus exact `Frontend quality recovery: clean` / `Frontend quality recovery owns global: no` and no closed Recovery receipt. Legacy/read-only accepts only `OPEN reason=not-required` with all frontend keys/marker/sidecars absent. Otherwise return to Phase 5/6 without starting or advancing code recovery. If a code fix makes routing/evidence stale, re-enter Phase 5/6 while global code Recovery remains active; the frontend gate accompanies it as non-owner and never clears it.

0.5. **Conformance serialization preflight.** When STATE declares `Conformance contract: 1`, run `${CLAUDE_PLUGIN_ROOT:-$CLAUDE_SKILL_DIR}/hooks/conformance-gate.sh .kimiflow/<slug>` (Codex: `$KIMIFLOW_PLUGIN_ROOT/hooks/conformance-gate.sh`) before every review entry/re-entry and require OPEN. Include the compact receipt plus decision checks in the existing Phase-7 review packet; do not add a reviewer. Any repair makes the content basis stale and therefore returns through Phase 6 before review resumes. After the named-path commit, `active-run.sh finish --write` uses terminal mode to require HEAD/index/worktree identity and repeats it transactionally after learning/outcome writes; a stale or different delivery cannot retire the run. Legacy/read-only audit/review parents remain OPEN/not-required; every approved code-changing audit slice or release-discovered repair executes as the separate contracted child run required by Phase 0.

0.75. **Trajectory preflight (code Convergence Contract 1).** Before spending a normal review call for round `N`, run `review-convergence-gate.sh preflight --run .kimiflow/<slug> --round <N>`. With mandatory schema-4 saturation, failures count per reproduced stable root class: A then B remains `OPEN/below-threshold`; only two failures of A require a schema-2 trajectory bound to `Trajectory class: A`. It cites the two chained receipts, exact same-class prior trajectory hashes, a falsifiable hypothesis/changed assumption, and typed checks. Rewording is insufficient: after a prior A trajectory, the action or executable/verifiable check must materially change. Missing or older source-saturation receipts fail closed; there is no global schema-1 trajectory fallback. CLOSED returns autonomously to diagnosis/plan/decomposition; never ask merely to continue.

1. **Fixed review basis + compact packet.** Before each review round, resolve and validate the base below, then run `review-convergence-gate.sh basis --run .kimiflow/<slug> --base <base> --details` and copy its exact `review_base_sha`, `review_target_sha`, `review_snapshot_sha256`, and per-path `review_files` into the mandatory schema-4 saturation receipt. Saturation rejects schema 1–3 unconditionally; delta and recovery accept only a schema-4 source, and its repair must use the current source-bound schema-3 shape. There is no legacy bypass. Schema 4 also binds exactly one `code-review-cascades/r<N>.md` scan-candidate file by path and digest; it uses the normal CANDIDATE grammar and `NONE` sentinel. The helper binds the round to HEAD plus the byte/type/existence state of every STATE-declared affected path; any later source mutation makes that receipt stale. Choose the base as follows: user-supplied validated base ref when present; otherwise schema-4+ runs with local Red/verification checkpoints use the active session's immutable, STATE-backed `started_head`; otherwise use the repository default branch for committed branch work or `HEAD` for working-tree-only review. A repair commit requires a fresh round and freshly resolved target; the base remains immutable. Compute the complete named run delta from committed, staged, unstaged, and `git ls-files --others --exclude-standard -- <named paths>`; include named new-file contents explicitly. Record refs/SHAs, exact commands, reviewed commits, untracked names, `spec_sources`, `standards_sources`, decisive Phase-6 evidence, and relevant canonical hunks in `CODE-REVIEW.md`; generated mirrors remain mechanically checked but are not duplicated semantically.
2. **Resolve topology, then saturate candidate axes.** Read → reference.md "Review rubric" (orchestrator only). Resolve the exact key with `adaptive-control.sh review-resolve`. `embedded` is allowed only by a mechanically valid, runtime/policy/prompt-gate-bound calibration receipt for the exact model fingerprint, opaque execution variant, role and routine task class. It runs one structured implementer self-review over the compact packet plus every mechanical test/diff/scope/secret/evidence gate; it does not spawn a semantic reviewer. A stable deterministic sampler upgrades exactly one of ten matching runs to `single-independent`, and profile/runtime/policy drift, regression, repeated failure, or a material audit finding revokes `embedded`. `single-independent` uses one fresh `top|cross_family_top` reviewer to cover every scheduled axis in one packet. `ensemble` is reserved for critical security/data/migration/public-API risk and uses separate narrow axes in parallel. Missing/unproven evidence resolves to `single-independent`. Pi: `code_review`; receipt required. If no stronger child or cross-family transport is available, the current strongest available orchestrator executes the same isolated packet, records the quality fallback, and continues; lack of leaf routing never closes the gate. Deliberately selected `balanced`/`cheap` support seats never issue semantic review verdicts. **Reviewers do not read reference.md** — inline each scheduled axis line + the CANDIDATE grammar + file-form constraints (column 0, no newline in the claim; nothing but CANDIDATE lines or the single sentinel `NONE`) into the prompt. On the first pass over a stable basis, explicitly require every independently evidenced BLOCKER/HIGH in the assigned axes, not only the strongest objection; later partial reruns stay targeted. `small` runs schedule at least **two** axes (`quick` alias: review light — ONE `spec-correctness` axis); add the third when the diff touches hooks, plugins, memory, launcher, APIs/contracts, multiple surfaces, or any high-risk path. On `small`, fold documented standards into R2 only when R3 is not scheduled; `large`/release-critical schedules all three. When independent review is scheduled, one axis (default `spec-correctness`) is cross-family by default when available — same transport/fallback as Phase 4 (→ reference.md "Model routing (per-role)"). The standard axes are:
   - **R1 spec-correctness:** trace requirements independently; find missing/partial/wrong behavior, unrequested scope, logic/edge regressions, and weakened/insufficient tests.
   - **R2 failure-security:** input validation, secrets/privacy, path handling, rollback/failure atomicity, partial writes; on `small` without R3, also apply the documented-standards/smell dimension.
   - **R3 standards-integration:** documented path-applicable project standards plus installed hooks/metadata/docs/launcher wiring, host parity (Claude/Codex), command/API/schema contracts; when Architecture Deliberation is active, verify the implementation still fits its operating envelope and selected invariant. Demand architecture change only with the executable falsifier or a concrete named-invariant violation; apply the compact smell baseline only as a heuristic.
   The first round for a stable PLAN runs all scheduled axes exactly once. Every later round on the same PLAN is an exact repair-delta review; it needs no Holdout/Shadow/Canary calibration. It reruns `spec-correctness` plus every path-required security/integration axis and carries unaffected axes. Critical risk does not force another full review. Add/delete/mode drift, more than eight changed paths, or another real architecture-boundary change requires a materially changed PLAN and one new full basis within the same global discovery budget; rewording is not a reset. Mechanical gates and final whole-intent verification never narrow.
   Each axis writes `.kimiflow/<slug>/code-review-candidates/r<N>-<axis>.md` using `CANDIDATE <SEVERITY> <ref> :: <claim> :: verify=<smallest check>` or `NONE`; when STATE declares Convergence Contract 1, the check is typed as `verify=command:<method>|verifier:<method>`.
2.1. **Pi visible-review override.** With an active FirstMate crew, `embedded` is not an independent code-review result. Kimiflow Main—not Captain—starts one visible `stage=confirmed` Scout for `quick`/`spec-correctness`, two for `small`, and three for `large`/release-critical, one per axis. These read-only Scouts may run in parallel against the exact Ship branch/commit. Only unavailable Main crew capability permits a folded Pi fallback, and that fallback is recorded explicitly. Main verifies every returned candidate and sends bounded findings or finalization clearance to the paused Ship.
3. **Orchestrator verification, axis-preserving.** Verify every candidate by targeted read, command, or reproduction; no-op commands and vague prose are invalid. Schema-4 dispositions add exactly one `cascade` field to the schema-3 shape. Every promoted class requires one bounded cascade object with stable root ID/cause/assumption, a valid member role, and exactly one typed-evidence `checked|not_applicable` probe for each `direct-callers,data-flow,shared-state,assumption-users,error-consequences` surface. Scan-discovered members first become normal candidates in the bound cascade file and then normal independently evidenced dispositions/findings. At most 32 promoted classes are accepted; each root group must have identical cause/assumption, exactly one root, and at least one scheduled-review origin. Non-promoted rows require `cascade:null`. `promoted` still requires reproduced evidence on a supported path that violates the contract and has concrete impact; it is the only outcome entering the finding aggregate and repair. `refuted` requires `not_reproduced`. `non_blocking` is allowed only for reproduced behavior outside the supported contract with no contract or material impact; security, privacy, data-loss, and irreversible impact can never be waived. `material_decision` is allowed only for a reproduced supported contract defect whose repair crosses the existing paid/privacy/scope/breaking/irreversible boundary; saturation returns `CLOSED/material-decision-required`, repair is unavailable, and the existing typed user gate must resolve authority before replacement promotion or park/fail. A runtime class may use text-only `verifier:` evidence for at most two rounds; the third same-class round needs executable `command:` evidence. Incremental review, carried classes, negative `RESOLVED` evidence, and the absolute closeout budget remain unchanged.
4. **Advisories.** First stage the run's named changed paths (`git add <named paths>` — never `-A`; the scans read the staged diff). Then run the bundled test-weakening scan `${CLAUDE_PLUGIN_ROOT:-$CLAUDE_SKILL_DIR}/hooks/test-weakening-scan.sh` over the staged diff → append its `FLAG` lines to `.kimiflow/<slug>/ADVISORIES.md`; if it can't be located or run, note it in STATE — never silently skip the advisory channel. Likewise run `hooks/secret-content-scan.sh` and `hooks/lsp-diagnostics.sh` when present. A smell with neither a documented-standard violation nor demonstrable impact is advisory-only; skip issues enforced by existing tooling. The Simplicity dimension still writes `FLAG`s to advisories (folded into an existing lens for `small`; dedicated prosecutor for `large` or size-tripwire).
5. **Fix + bounded recovery.** Only promoted BLOCKER/HIGH classes enter `review-repairs/r<N>.json`. A schema-4 cascade requires a source-bound schema-3 repair receipt whose group IDs, root-cause text and class sets exactly match the authenticated cascade groups and whose checks retain every member's authoritative typed verifier; one shared change may repair the common cause, but one shared check cannot hide a member. Schema-1/2 repair receipts are rejected. Non-blocking/refuted candidates never consume a repair round, and a pending `material_decision` cannot enter repair. In the next schema-4 delta saturation, every source class is partitioned exactly once: it is either byte-exactly carried or separately `RESOLVED` by `not_reproduced` evidence using its original verifier and bound to the exact current delta digest. Rounds 1–3 remain the complete semantic discovery budget, with path-required delta axes after the first full review. Round 4 is resolution-only closeout with `NONE` candidate files, zero carried classes, only targeted context-bound negative `RESOLVED` evidence, and normally a mandatory delta; an open class can never finish green. If the authenticated Round-3 recovery changed PLAN and therefore makes that delta inexpressible, one full closeout is accepted only after the schema-4 source saturation is fully revalidated against its frozen basis, candidate files, dispositions, evidence and aggregate, with the exact Round-3 scheduled axes, the exact source-bound schema-3 repair receipt, and negative `RESOLVED` evidence using every repaired source class's authoritative typed verifier and bound to both that repair receipt and the current closeout saturation receipt. Unchanged-plan, narrowed-axis, precomputed/evidence-free, verifier-drifted, invalid-source, source-drifted and unauthenticated full receipts remain closed. Recovery counts repeated strategies per stable class and requires a materially changed falsifiable route for that class; it never resets the global cap. `review-limit-reached` preserves unresolved evidence and ends automatic ping-pong.
6. **Atomic local commit.** Read → reference.md "Commit hygiene". Triage every advisory autonomously with evidence: dismiss non-impact with a recorded reason or promote it to a real finding and return to review. Show a short summary, `git status`, and `git diff --staged`; at `quiet`, keep it to decisive sentences. Snapshot the NUL-delimited staged paths before adding the exact named run-owned paths; classify every pre-existing foreign staged path and leave it staged and untouched. Require no unstaged bytes in the named paths, then commit only those pathspecs with `git commit --only -m "<message>" -- <named paths>`; verify the new commit contains exactly the intended paths and the foreign staged snapshot is unchanged. Schema 4+ does this automatically under the original build authority: no `git add -A`, no co-author/AI trailer, tests green; if verified Phase-5 checkpoints already contain the complete reviewed change, do not create an empty commit. Push, release, destructive migration, and external publication remain separately authorized. Schema 3 retains its legacy `await-user --kind commit` gate. **(large)** write the verified Phase-6 command to local/untracked `.kimiflow/test-gate` when absent. **(audit)** keep one verified slice = one reviewable diff = one local commit; never batch slices.
7. **Learning loop + project memory — required before `Status: done`.** Run `MR review-run --run .kimiflow/<slug> --write` after verification/review. A structured learning with one `Confirmed root cause:` may add 1–8 exact `Source evidence: <repo-path>:<line>` rows; only current regular non-symlink source files outside `.kimiflow` are accepted, and existing evidence fingerprints make the learning stale when any cited bytes change. Too-short/generic/unsafe/malformed learning evidence blocks the write. If no durable learning exists, use an explicit `--skip "<reason>"`. Then require `MR verify-run --run .kimiflow/<slug>` OPEN before completion; the rest of memory, outcome, provider/Vault, and proposal behavior remains unchanged and local-first.
8. **Project-map auto-refresh** (recommended, non-blocking). After Phase-6 verify, run `PMS refresh --changed` (`PMS` = `${CLAUDE_PLUGIN_ROOT:-$CLAUDE_SKILL_DIR}/hooks/project-map-status.sh`; Codex: `KIMIFLOW_HOST=codex` + `KIMIFLOW_PLUGIN_ROOT`) so the sections of the files this run touched are re-hashed back to `current`, deleted members are pruned, new files under a known section prefix are adopted (+sha256), and each refreshed `.sh` section's symbol index is rebuilt. `NEW-FILE` lines are structure hints only — no auto-facts; durable learnings still flow through the gated learning loop above. Skip silently when there is no `.kimiflow/project/INDEX.json`. The Stop-hook map-staleness nudge (`hooks/map-staleness-nudge.sh`) is the safety net that surfaces any residual staleness. → reference.md "Project Map Bootstrap".
8.5 **Adaptive maintenance (schema 5, best effort, no user gate).** A command adapter may attest an actually executed distinct `balanced|cheap` candidate only through its validated `turn.completed.model_route` plus measured usage. Terminal runner closure automatically derives risk, success/failure, retries and every material review finding, then records one evidence-bound sample per role; caller-provided model labels never qualify. `hooks/adaptive-control.sh model-record --run .kimiflow/<slug>` is only an idempotent maintenance replay and requires the same adapter receipt. The next command-adapter payload resolves configured roles from at least five clean comparable samples and falls back to `top` after any failed terminal run or material finding. Then run `MR retention archive --write` once: it may archive at most one inactive run with explicit terminal `Status: done|failed|aborted`, older than 30 days and outside the newest 20, after mode-0600 archive/manifest verification. `Phase 7: done` alone is not terminal. `no_eligible_run` and maintenance errors are visible nonblocking receipts; current, active, recent and nonterminal runs are never touched.
    After fixed terminal review evidence, record the exact review calibration outcome once with
    `adaptive-control.sh review-record`; an implementer's unevidenced assertion never counts as clean.
9. **Close state.** For phase-read runs, read/record Phase 7 before `hooks/active-run.sh finish --write`; finish checks fresh reads through Phase 7 and, when declared, the pinned valid Execution Contract journal, writes the automatic `OUTCOME-EVALUATION.json`, updates the local strategy ledger when evidence is promotable, then retires the session. Missing, malformed, symlinked, oversized, or selector-mismatched execution evidence fails closed and is repaired autonomously. After the local commit and learning review are open, set all phases done and `Status: done`. From the primary tree, `finish --write` also detects this run's registered noncurrent exceptional tree and invokes the guarded retirement internally; it succeeds only for the clean, unlocked, terminal, Kimiflow-owned tree, atomically archives the complete checkout plus its identity-matched Git metadata, includes both archive paths in `workspace_retirement`, and preserves its branch. `fail` and `abort` perform the same safe retirement; `park` retains the tree for resume. A dirty/changed target is reported `deferred` and remains untouched.
