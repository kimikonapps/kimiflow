# Kimiflow for Codex and Claude Code

Read `SKILL.md` at the installed plugin root once. The root is two levels above this file.
Use the user's chosen model and the host's own task history, plan mode, tools and workspace isolation.
Do not create phase state, a reviewer ensemble or memory ledgers. Resolve helper paths against the
installed plugin, never a project's similarly named scripts.

For user-selected delegation, follow the installed `references/planner-worker.md`. In Claude Code, run
the worker as a subagent with an explicitly chosen, cheaper `model`, and keep planning and review in
the session model; a subagent without an explicit model inherits the session model and is not a cheaper
worker. In Codex, use the host's native delegation the same way. Use the host's worktree isolation only
when a task needs it.

For legacy Flow-schema state or managed `workflow_context`, read installed `MIGRATION.md`; the old
controller is not part of this version. Ordinary new tasks follow the short shared working agreement.
