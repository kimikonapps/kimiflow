# Kimiflow Scaling Knobs

Detailed optional capacity knobs for Kimiflow runs. The always-loaded driver keeps only the entry rules; this file carries the expanded contract.

## Scaling knobs (defaults scale with scope — the cross-family lens is ON when available; extras stay OFF until enabled within the agent budget; record in STATE.md)

> **Display verbosity is NOT a knob.** Always-on, changes only visible output volume — never gates, cost, quality, or behavior. Never couple it to anything gate- or cost-related (→ reference.md "Display verbosity").

- **Solo-dev implementation (fixed default):** one sequential implementation path per run. Clean/free primary has zero worktree overhead; dirty/busy primary automatically routes one concurrent run into the single locked, owned broker worktree and FIFO-queues later runs. Path/contract declarations, current-plan write gates, merge-tree preflight, argv checks, ff-only delivery and ancestry-gated archive retirement are mechanical. Read/review agents do not create trees; there is no best-of-N implementation fan-out.
- **Cross-family reviewer — default when independent review is scheduled:** one plan-gate lens and one scheduled code-review lens route to a different model family whenever a cross-family CLI is available. An eval-proven embedded routine review skips that call except for its deterministic 1-in-10 audit sample; critical risk still uses the ensemble. On a Claude Code host the seat is an **ordered chain** — default Codex → Gemini (Antigravity `agy`, pinned `Gemini 3.5 Flash (High)`, `--sandbox` + no-tools) → same-family. Configure/opt-out via `.kimiflow/cross-family`: `off` (disable), or an explicit order like `auto gemini,codex` / `auto gemini` (Gemini only, skip Codex — useful where Codex times out). Mechanics → reference.md "Model routing (per-role)" → "Opt-out & order".
- **Per-seat tier/execution variant — evidence-routed, not a fixed vocabulary:** the strongest available `top` model owns orchestration, planning, Phase-2 synthesis, review verdicts, independent semantic verification, and risky diagnosis. A deliberately selected `balanced` value-tier model is the normal implementer; `cheap` handles only deterministic bounded support. Start every role at the adapter-declared host default and promote opaque cheaper/deeper variants only from comparable clean outcomes. Never infer effort or thinking controls from a model name; keep the variant stable in one cache lineage. Self-verifying profiles can remove routine duplicate semantic review only after local calibration, while all mechanical gates remain. Mechanics → reference.md "Model routing (per-role)".
- **Adaptive execution profiles — fixed, not an agent multiplier:** Execution Contract 1 chooses only `compact|standard|critical`; `normal|recovery` changes strategy without adding a quality tier. Budget pressure is cumulative and may prune optional discovery/review breadth at `hard`, but never mandatory gates or evidence. There is no dynamic topology, best-of-N expansion or daemon; the one-slot worktree broker changes only workspace routing. Mechanics → reference.md "Active Session Contract".
- **Simplicity dimension:** fold it into the scheduled review packet by default. A dedicated prosecutor is reserved for a size-tripwire or critical ensemble; an embedded routine review never adds a second model merely for style. Advisory only.
- **Repeated verdicts only on evidence:** do not sample the same verdict three times by default. Additional independent passes occur only for a critical ensemble, the deterministic embedded audit sample, or a reproduced regression/recovery class.
- **Deeper debugging:** for a stubborn bug, stop patching and run a systematic, hypothesis-first pass (reproduce → isolate → root-cause) before further edits.
- **Hard test-gate (opt-in, per project):** kimiflow ships a Stop hook (`hooks/`) that blocks finishing on red tests — see → reference.md "Hard test-gate" to enable.
- **Anti-reward-hacking hardening (critical code):** held-out/hidden tests, stricter diff inspection for test manipulation.
- **Behavioral evals (out-of-CI, on-demand):** pressure-test the gates against rationalization with subagents loaded with the real skill — see `evals/` (the `testing-skills-with-subagents` tier). Slow/LLM-judged; never wired into CI.
