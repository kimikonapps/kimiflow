## 🟡 Phase 4 — Plan-gate (binary; three global rounds maximum)

- **Prose quality (same model pass):** Before saving or reviewing decision-bearing prose, read all of `${CLAUDE_PLUGIN_ROOT:-$CLAUDE_SKILL_DIR}/references/workflow-prose-quality.md` (Codex: `$KIMIFLOW_PLUGIN_ROOT/references/workflow-prose-quality.md`) and apply it before output; add no agent, call, step, or gate.

Read → reference.md "Review rubric".

0. **Mechanical preflight:** run `${CLAUDE_PLUGIN_ROOT:-$CLAUDE_SKILL_DIR}/hooks/plan-blocker-gate.sh .kimiflow/<slug>` (Codex: `KIMIFLOW_HOST=codex` and `KIMIFLOW_PLUGIN_ROOT`). `OPEN` is required before reviewers. For phase-read runs, record reads through Phase 4. New Convergence-Contract runs carry `Plan review contract: 1` plus `Plan review profile: standard|contract`; `contract` requires a current pairwise `CONTRACT-MATRIX.json`. Audit keeps its existing profile. Confirm every AC maps to a task/test and no orphan task exists.
1. **Freeze once, review broadly, then edit once.** Hash the exact current `PLAN.md` (audit: `AUDIT.md` plus `AUDIT-INTENT.md`), dispatch every scheduled lens in parallel on those same bytes, and do not mutate the basis artifacts until every candidate/findings file for the round exists. `small` schedules exact lens IDs `a,b`; `large`, audit, and profile=`contract` schedule exact IDs `a,b,c`; the gates reject narrower or reordered lists. If independent seats are unavailable, run the same isolated packets sequentially on the frozen basis and record the fallback; deliberately selected `balanced`/`cheap` seats never issue the verdict. One scheduled lens is cross-family by default when available (prefer C for contract profile, otherwise B). Pi Main uses visible `stage=confirmed` Scouts when its crew is active; Captain and the implementation Ship never self-review.
   - **A — intent/completeness/subtraction:** trace every requirement to measurable AC, task, artifact, and check; find contradictions or invented scope; remove unsupported work.
   - **B — failure/security/evidence:** concrete error, security, data-loss, identity/replay, path/evidence, rollback, and architecture-falsifier risks; demand architecture change only with an exact failing scenario/executable check or named-invariant violation. Audit also refutes every deletion by hunting live callers.
   - **C — state/contract/aggregation:** enumerate legal and illegal states, lifecycle and time order, missing/invalid classification, cross-row identity, derived formulas, denominators, thresholds, and verdict precedence. For profile=`contract`, actively falsify `CONTRACT-MATRIX.json` and report uncovered combinations.
   - A BLOCKER/HIGH needs a cited intent/AC, required constraint, current compatibility rule, project standard, or demonstrable security/data-loss failure. Optional robustness, taste, future scope, and hypothetical unsupported requirements do not block. Each reviewer enumerates **all** independently evidenced material candidates; never stop after the first.
2. **Candidate and coverage contract (`Plan review contract: 1`).** Each `.kimiflow/<slug>/plan-review-candidates/r<N>-<lens>.md` starts with `BASIS plan_sha256=<64hex>`, contains at least one `COVERAGE <domain> :: status=checked|not_applicable :: evidence=<ref>` line, then either `NONE` or every candidate as `CANDIDATE <SEVERITY> <ref> :: <claim> :: family=<stable-family> :: verify=command:<method>|verifier:<method>`. Across the scheduled lenses the exact domains are `intent-trace,state-space,identity-binding,evidence-safety,time-lifecycle,aggregation-verdict,scope-subtraction`. A bare `NONE` is invalid. Reviewers do not read `reference.md`; inline the relevant lens, evidence threshold, grammar, assigned coverage domains, and prose-quality path in <18 lines.
3. **Verify and batch by root family.** The orchestrator runs every BLOCKER/HIGH candidate's exact method, attempts refutation, and records `promoted|refuted|non_blocking`. Each disposition evidence file is exactly one `REVIEW_EVIDENCE class=<id> :: verify=<exact candidate method> :: outcome=reproduced|not_reproduced :: <detail>` line: promotion uses the stable class and `reproduced`; `refuted` uses `candidate-<first54hex of candidate_id>` and `not_reproduced`; `non_blocking` uses that candidate class and `reproduced`. Authoritative findings retain the same digest-pinned evidence. Do not repair while candidates are still arriving. Group all promoted classes by one root cause, then check each family across `upstream-requirements,sibling-states,downstream-outputs,boundary-values,failure-classification`. Repair the complete family once; never patch one sentence and defer its siblings.
4. **Saturation receipt:** write `.kimiflow/<slug>/plan-review-saturation/r<N>.json` schema 1 with exact `round`, `plan_sha256`, ordered `lenses`, candidate/finding file digests, one disposition per emitted BLOCKER/HIGH candidate, and family groups containing `id,classes,root_cause,checks`. Append exactly one immutable `<!-- kimiflow:plan-saturation round=<N> receipt=<sha256(rN.json)> plan=<plan_sha256> previous=none|<prior receipt sha256> -->` to `RECOVERY.md`; its plan hash must equal the plan strategy baseline or a recovery `after` hash. Then run `active-run.sh pin-plan-saturation --run .kimiflow/<slug> --round N --expect <lensCSV> --write`: it validates the complete receipt first and immutably anchors the chain in the separately controlled Active-Run session state. Every family check has `status=checked|not_applicable` plus evidence. Now run strict `plan-review-gate.sh saturation --run .kimiflow/<slug> --round <N> --expect <lensCSV>`; `OPEN/saturated` is required before the resolver. Every later call revalidates the Active-Run pins, append-only marker chain, all earlier receipts, and their artifact/evidence digests. The helper rejects stale reviewer bases, rewritten history, missing domains, silent candidate drops, evidence/verifier mismatch, aggregate mismatch, incomplete sibling sweeps, family drift, and material candidates in round 3. Audit uses its direct immutable findings ledger instead of PLAN saturation.
5. **Exactly three global round roles:** round 1 = exhaustive parallel discovery; batch-repair all verified families. Round 2 = verify the complete repair plus a targeted family/counterexample sweep; batch any remaining verified families. Round 3 = resolution-only whole-contract closeout; no new BLOCKER/HIGH candidate is permitted. Rounds and findings remain global, monotonically increasing, and immutable across every PLAN/model/strategy change. `C=3` is absolute; no recovery epoch, rewording, model switch, clean file, or new PLAN hash can start round 4.
6. **Binary resolver:** before round 1 append `<!-- kimiflow:strategy gate=plan epoch-start=1 fingerprint=<sha256(PLAN.md)> -->` to `RECOVERY.md` (audit fingerprints `AUDIT.md` under its compatible direct ledger). Persist `Review gate: plan`, current epoch fields with cap ≤3, `Strategy fingerprint`, and `Recovery: active|clean`. Contracted plans run `resolve-review-gate.sh .kimiflow/<slug>/findings --round <N> --expect <lensCSV> --gate plan --epoch-start <S> --cap 3 --finding-contract 1`; Flow-5 audits use the same explicit gate/bounds with `--expect a,b,c` and their compatible findings grammar. Only `OPEN/clean` advances; MEDIUM/LOW remain advisory. A prior contracted class needs exact digest-pinned negative evidence; `NONE` cannot waive it.
7. **Routing:** `incomplete|malformed|unproven-resolution` repairs transport/evidence in the same round where possible. `open-findings|root-class-repeated|oscillation|reappeared|cap-reached` changes the technical strategy within the remaining global rounds. A material defect at round 3 or any `review-limit-reached` preserves the blocker and routes to AC-preserving decomposition or an explicit follow-up decision—never an automatic fourth round and never a silent downgrade. Technical recovery reuses evidence, reruns the plan blocker/matrix, and may change the PLAN only between rounds. User input remains limited to a genuinely material authority/scope/risk decision.
8. Append a compact round summary to `REVIEW.md`. On `OPEN/clean`, mark recovery clean and continue. `--prepare` parks with phases 0–4 done and prints `/kimiflow --resume <slug>`.
9. **Pre-build decision boundary.** Show **Will build/fix · Not included · Important decisions · Risks/irreversibility · Effort**. For schema 4+, record `Build risk: none|required` and run `resolve-build-gate.sh decide --state .kimiflow/<slug>/STATE.md`; risk `none` continues, while a material typed risk pauses once. Schema-3 runs retain their legacy preview behavior. → reference.md "Build Preview / Risk Gate".
