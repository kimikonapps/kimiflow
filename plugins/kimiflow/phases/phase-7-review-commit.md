## 🟢 Phase 7 — Evidence-routed code review against specs → fix → commit-gate

0. **Frontend serialization preflight.** Before every Phase-7 entry/re-entry, run `${CLAUDE_PLUGIN_ROOT:-$CLAUDE_SKILL_DIR}/hooks/frontend-quality-gate.sh .kimiflow/<slug> --write` (Codex: `$KIMIFLOW_PLUGIN_ROOT/hooks/frontend-quality-gate.sh`). Contract 1 requires OPEN plus exact `Frontend quality recovery: clean` / `Frontend quality recovery owns global: no` and no closed Recovery receipt. Legacy/read-only accepts only `OPEN reason=not-required` with all frontend keys/marker/sidecars absent. Otherwise return to Phase 5/6 without starting or advancing code recovery. If a code fix makes routing/evidence stale, re-enter Phase 5/6 while global code Recovery remains active; the frontend gate accompanies it as non-owner and never clears it.

0.5. **Conformance serialization preflight.** When STATE declares `Conformance contract: 1`, run `${CLAUDE_PLUGIN_ROOT:-$CLAUDE_SKILL_DIR}/hooks/conformance-gate.sh .kimiflow/<slug>` (Codex: `$KIMIFLOW_PLUGIN_ROOT/hooks/conformance-gate.sh`) before every review entry/re-entry and require OPEN. Include the compact receipt plus decision checks in the existing Phase-7 review packet; do not add a reviewer. Any repair makes the content basis stale and therefore returns through Phase 6 before review resumes. After the named-path commit, `active-run.sh finish --write` uses terminal mode to require HEAD/index/worktree identity and repeats it transactionally after learning/outcome writes; a stale or different delivery cannot retire the run. Legacy/read-only audit/review parents remain OPEN/not-required; every approved code-changing audit slice or release-discovered repair executes as the separate contracted child run required by Phase 0.

0.75. **Trajectory preflight (code Convergence Contract 1).** Before spending a normal review call for round `N`, run `review-convergence-gate.sh preflight --run .kimiflow/<slug> --round <N>`. Fewer than two failed code strategies returns `OPEN/below-threshold`. At the hard boundary, only a current PLAN-bound `review-trajectories/source-r<last>.json` citing the two chained recovery receipts, exact prior-trajectory hashes, a never-repeated falsifiable hypothesis/action/assumption/check identity, and typed checks returns `OPEN/trajectory-ready`. The action is `replan|decompose|architecture_reset|new_falsifier`. CLOSED returns autonomously to diagnosis/plan/decomposition; never ask the user merely to continue.

1. **Fixed review basis + compact packet.** Before each review round, resolve and validate the base below, then run `review-convergence-gate.sh basis --run .kimiflow/<slug> --base <base> --details` and copy its exact `review_base_sha`, `review_target_sha`, `review_snapshot_sha256`, and per-path `review_files` into a schema-2 saturation receipt. The helper binds the round to HEAD plus the byte/type/existence state of every STATE-declared affected path; any later source mutation makes that receipt stale. Choose the base as follows: user-supplied validated base ref when present; otherwise schema-4+ runs with local Red/verification checkpoints use the active session's immutable, STATE-backed `started_head`; otherwise use the repository default branch for committed branch work or `HEAD` for working-tree-only review. A repair commit requires a fresh round and freshly resolved target; the base remains immutable. Compute the complete named run delta from committed `git diff <base>...<target>`, tracked worktree `git diff <target>`, staged state, and `git ls-files --others --exclude-standard -- <named paths>`; include new-file contents explicitly. Only this combined set being empty may end without reviewers. Record refs/SHAs, every exact command, reviewed commits, and untracked names in `CODE-REVIEW.md`; every reviewer receives the same basis and new-file payload. Discover and record `spec_sources` in precedence order (explicit user source → run-local `ACCEPTANCE.md` plus `INTENT.md`/`PROBLEM.md` → issue/PR refs in reviewed commits → matching `docs/`, `specs/`, `.scratch/` material) and `standards_sources` (`AGENTS.md`/`CLAUDE.md`, `CONTRIBUTING.md`, `CODING_STANDARDS.md`, `.kimiflow/STANDARDS.md`, relevant architecture docs). If no spec exists, mark the Spec part unavailable instead of inventing intent; the correctness/regression part still runs against observable contracts. Build one compact packet: source references + only relevant excerpts, changed-file list, `git diff --stat`, relevant hunks plus complete named new files, diagnosis/repro artifacts when present, decisive Phase-6 evidence, and exact verification commands.
2. **Resolve topology, then saturate candidate axes.** Read → reference.md "Review rubric" (orchestrator only). Resolve the exact key with `adaptive-control.sh review-resolve`. `embedded` is allowed only by a mechanically valid, runtime/policy/prompt-gate-bound calibration receipt for the exact model fingerprint, opaque execution variant, role and routine task class. It runs one structured implementer self-review over the compact packet plus every mechanical test/diff/scope/secret/evidence gate; it does not spawn a semantic reviewer. A stable deterministic sampler upgrades exactly one of ten matching runs to `single-independent`, and profile/runtime/policy drift, regression, repeated failure, or a material audit finding revokes `embedded`. `single-independent` uses one fresh `top|cross_family_top` reviewer to cover every scheduled axis in one packet. `ensemble` is reserved for critical security/data/migration/public-API risk and uses separate narrow axes in parallel. Missing/unproven evidence resolves conservatively to `single-independent`, never to an extra ensemble. If no stronger child or cross-family transport is available, the current strongest available orchestrator executes the same isolated packet, records the quality fallback, and continues; lack of leaf routing never closes the gate. Deliberately selected `balanced`/`cheap` support seats never issue semantic review verdicts. **Reviewers do not read reference.md** — inline each scheduled axis line + the CANDIDATE grammar + file-form constraints (column 0, no newline in the claim; nothing but CANDIDATE lines or the single sentinel `NONE`) into the prompt. On the first pass over a stable basis, explicitly require every independently evidenced BLOCKER/HIGH in the assigned axes, not only the strongest objection; later partial reruns stay targeted. `small` runs schedule at least **two** axes (`quick` alias: review light — ONE `spec-correctness` axis); add the third when the diff touches hooks, plugins, memory, launcher, APIs/contracts, multiple surfaces, or any high-risk path. On `small`, fold documented standards into R2 only when R3 is not scheduled; `large`/release-critical schedules all three. When independent review is scheduled, one axis (default `spec-correctness`) is cross-family by default when available — same transport/fallback as Phase 4 (→ reference.md "Model routing (per-role)"). The standard axes are:
   - **R1 spec-correctness:** trace requirements independently; find missing/partial/wrong behavior, unrequested scope, logic/edge regressions, and weakened/insufficient tests.
   - **R2 failure-security:** input validation, secrets/privacy, path handling, rollback/failure atomicity, partial writes; on `small` without R3, also apply the documented-standards/smell dimension.
   - **R3 standards-integration:** documented path-applicable project standards plus installed hooks/metadata/docs/launcher wiring, host parity (Claude/Codex), command/API/schema contracts; when Architecture Deliberation is active, verify the implementation still fits its operating envelope and selected invariant. Demand architecture change only with the executable falsifier or a concrete named-invariant violation; apply the compact smell baseline only as a heuristic.
   Every stable basis starts with all scheduled axes. After an evidenced repair, `adaptive-control.sh review-cascade-resolve --run .kimiflow/<slug> --write` may lease unaffected axes only for the exact model/variant/role/task/runtime/policy/prompt fingerprint. Activation requires clean Holdout, Shadow and five ordered Canary A/B outcomes with equal quality/verification, no missed material findings/retries/extra rounds, at most two cascade rounds, and fewer tokens. New fingerprints recalibrate. Critical risk, broad/add-delete/mode deltas, regression/repeated failure, the one-in-ten audit, stale receipts, or path-sensitive axes force `full`; only active, non-audit `selective` may narrow the semantic rerun. Mechanical gates and final whole-intent verification never narrow.
   Each axis writes `.kimiflow/<slug>/code-review-candidates/r<N>-<axis>.md` using `CANDIDATE <SEVERITY> <ref> :: <claim> :: verify=<smallest check>` or `NONE`; when STATE declares Convergence Contract 1, the check is typed as `verify=command:<method>|verifier:<method>`.
3. **Orchestrator verification, axis-preserving.** Verify candidates by targeted read, command, or reproduction. BLOCKER/HIGH requires active refutation with its `verify=` check and full code path; reject refuted candidates. `true`, `:`, standalone `echo`/`printf`, and vague prose are not falsifiers. In `CODE-REVIEW.md`, preserve the three axis headings, sources, evidence, and outcomes; link cross-axis duplicates but promote one defect once with all labels. Legacy promotion keeps the existing FINDING grammar. Under Convergence Contract 1, derive a stable class from the violated AC/invariant, execute the typed check, and promote only `outcome=reproduced` with its one-line regular `review-evidence/` receipt and SHA-256. Clearing a prior class requires the same method with `outcome=not_reproduced` plus `RESOLVED`; `NONE` cannot clear it. Write schema-2 `review-saturation/r<N>.json` with scheduled/actual axes, candidate digests, step-1 basis, dispositions, carried classes, and `delta_receipt=null` for full review. A leased partial review first binds previous saturation, repair, unchanged PLAN, current per-path snapshot, changed paths, rerun/carried axes, and route receipt in `review-deltas/r<N>.json`; require `delta` → `OPEN/selective-review-ready` and store its path+digest. Require `saturation ... --axes <actual-csv>` → `OPEN/saturated` before resolution. Schema 1 remains resumable; only the aggregate promoted file is counted.
4. **Advisories.** First stage the run's named changed paths (`git add <named paths>` — never `-A`; the scans read the staged diff). Then run the bundled test-weakening scan `${CLAUDE_PLUGIN_ROOT:-$CLAUDE_SKILL_DIR}/hooks/test-weakening-scan.sh` over the staged diff → append its `FLAG` lines to `.kimiflow/<slug>/ADVISORIES.md`; if it can't be located or run, note it in STATE — never silently skip the advisory channel. Likewise run `hooks/secret-content-scan.sh` and `hooks/lsp-diagnostics.sh` when present. A smell with neither a documented-standard violation nor demonstrable impact is advisory-only; skip issues enforced by existing tooling. The Simplicity dimension still writes `FLAG`s to advisories (folded into an existing lens for `small`; dedicated prosecutor for `large` or size-tripwire).
5. **Fix + autonomous recovery.** For confirmed BLOCKER/HIGH, first write `review-repairs/r<N>.json` and pass the Phase-5 repair-entry gate: cover every open stable class once, group common roots, order dependencies, name typed checks, and reuse at least one covered finding check per group. Repair the batch and compute the exact per-path delta. Full review is default. An active lease still reruns `spec-correctness`; security/privacy/auth/payment/migration paths add `failure-security`, and hooks/plugins/phases/rendered docs/manifests add `standards-integration`. Unknown risk or boundary drift forces full review. Carry only still-applicable classes with exact evidence; never waive a finding. Follow Phase 4's strategy-epoch contract with gate=`code`; update PLAN when strategy changes and pin one pre-round-1 baseline. Resolve with globally increasing rounds, `B=2` for quick/small or `B=3` for large/release-critical, `C=S+B-1`, STATE `Review gate: code`, and all mandatory `resolve-review-gate.sh ... --expect code-verified --gate code --epoch-start <S> --cap <C> --review-axes <actual-csv> --finding-contract 1` flags. Repair malformed/unproven transport; batch `open-findings`. Repetition/oscillation/cap changes strategy and records chained PLAN before/after hashes, then returns through diagnosis/build/verification without user confirmation. After two failed strategies, trajectory preflight requires a PLAN-recorded replan/decomposition/architecture reset/new falsifier with action, hypothesis, changed assumption, and checks; one independent recovery solver may supply it. `OPEN/clean` clears Recovery before commit. Never reset valid rounds or repeat build approval. → reference.md "Review rubric".
6. **Atomic local commit.** Read → reference.md "Commit hygiene". Triage every advisory autonomously with evidence: dismiss non-impact with a recorded reason or promote it to a real finding and return to review. Show a short summary, `git status`, and `git diff --staged`; at `quiet`, keep it to decisive sentences. Snapshot the NUL-delimited staged paths before adding the exact named run-owned paths; classify every pre-existing foreign staged path and leave it staged and untouched. Require no unstaged bytes in the named paths, then commit only those pathspecs with `git commit --only -m "<message>" -- <named paths>`; verify the new commit contains exactly the intended paths and the foreign staged snapshot is unchanged. Schema 4+ does this automatically under the original build authority: no `git add -A`, no co-author/AI trailer, tests green; if verified Phase-5 checkpoints already contain the complete reviewed change, do not create an empty commit. Push, release, destructive migration, and external publication remain separately authorized. Schema 3 retains its legacy `await-user --kind commit` gate. **(large)** write the verified Phase-6 command to local/untracked `.kimiflow/test-gate` when absent. **(audit)** keep one verified slice = one reviewable diff = one local commit; never batch slices.
7. **Learning loop + project memory — required before `Status: done`.** Run `MR review-run --run .kimiflow/<slug> --write` after verification/review — it records the learning set in `.kimiflow/project/LEARNINGS.jsonl`, refreshes bounded memory/index/metrics/proposal/provider state, and returns a compact notification. `review-run` is **quality-gated**: too-short/generic learnings, missing evidence, or unsafe memory content block the write. If the run has no durable learning, use `MR review-run --run .kimiflow/<slug> --write --skip "<reason>"` so the skip is explicit. A verified architecture principle becomes a durable standard only when its exact applicability is known: call `MR standards record --scope <glob> --type <invariant|constraint|preference|heuristic|legacy> --rule <one-line> --evidence <ref> --write`; never infer a global scope. Otherwise keep it run-local or record the verified choice in Decisions. Then run `MR verify-run --run .kimiflow/<slug>`; a CLOSED result blocks completion, including stale/changed evidence fingerprints. Do not invoke outcome evaluation manually: `active-run.sh finish --write` evaluates the final strategy transactionally after these gates; `park|fail|abort` evaluate best-effort without delaying safe closure. User/workflow preferences go through `record --scope user` (local-only). Provider/Vault safety: neither `.kimiflow/` nor repo files store the key; prefetch/sync handoffs export only freshly verified current, non-private, non-security learnings; it never patches skills or writes external notes blindly — approved skill candidates become review-only drafts under `.kimiflow/project/SKILL-DRAFTS/`. Everything else (history search, usage/economics/usefulness metrics, `consolidate`/`propose` curation, the provider subcommands): → reference.md "Memory Router & Learning Loop".
8. **Project-map auto-refresh** (recommended, non-blocking). After Phase-6 verify, run `PMS refresh --changed` (`PMS` = `${CLAUDE_PLUGIN_ROOT:-$CLAUDE_SKILL_DIR}/hooks/project-map-status.sh`; Codex: `KIMIFLOW_HOST=codex` + `KIMIFLOW_PLUGIN_ROOT`) so the sections of the files this run touched are re-hashed back to `current`, deleted members are pruned, new files under a known section prefix are adopted (+sha256), and each refreshed `.sh` section's symbol index is rebuilt. `NEW-FILE` lines are structure hints only — no auto-facts; durable learnings still flow through the gated learning loop above. Skip silently when there is no `.kimiflow/project/INDEX.json`. The Stop-hook map-staleness nudge (`hooks/map-staleness-nudge.sh`) is the safety net that surfaces any residual staleness. → reference.md "Project Map Bootstrap".
8.5 **Adaptive maintenance (schema 5, best effort, no user gate).** A command adapter may attest an actually executed distinct `balanced|cheap` candidate only through its validated `turn.completed.model_route` plus measured usage. Terminal runner closure automatically derives risk, success/failure, retries and every material review finding, then records one evidence-bound sample per role; caller-provided model labels never qualify. `hooks/adaptive-control.sh model-record --run .kimiflow/<slug>` is only an idempotent maintenance replay and requires the same adapter receipt. The next command-adapter payload resolves configured roles from at least five clean comparable samples and falls back to `top` after any failed terminal run or material finding. Then run `MR retention archive --write` once: it may archive at most one inactive run with explicit terminal `Status: done|failed|aborted`, older than 30 days and outside the newest 20, after mode-0600 archive/manifest verification. `Phase 7: done` alone is not terminal. `no_eligible_run` and maintenance errors are visible nonblocking receipts; current, active, recent and nonterminal runs are never touched.
    After fixed terminal review evidence, record the exact review calibration outcome once with
    `adaptive-control.sh review-record`; an implementer's unevidenced assertion never counts as clean.
9. **Close state.** For phase-read runs, read/record Phase 7 before `hooks/active-run.sh finish --write`; finish checks fresh reads through Phase 7 and, when declared, the pinned valid Execution Contract journal, writes the automatic `OUTCOME-EVALUATION.json`, updates the local strategy ledger when evidence is promotable, then retires the session. Missing, malformed, symlinked, oversized, or selector-mismatched execution evidence fails closed and is repaired autonomously. After the local commit and learning review are open, set all phases done and `Status: done`. From the primary tree, `finish --write` also detects this run's registered noncurrent exceptional tree and invokes the guarded retirement internally; it succeeds only for the clean, unlocked, terminal, Kimiflow-owned tree, atomically archives the complete checkout plus its identity-matched Git metadata, includes both archive paths in `workspace_retirement`, and preserves its branch. `fail` and `abort` perform the same safe retirement; `park` retains the tree for resume. A dirty/changed target is reported `deferred` and remains untouched.
