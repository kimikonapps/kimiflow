## ⚪ Phase 0 — Setup, Routing & Scope-Gate

0. **Display verbosity preflight (first, before launcher/menu prose).** Standalone Pi resolves `RV` as `<loaded-kimiflow-package-root>/hooks/resolve-verbosity.sh`; never guess an install path, and invoke it with `KIMIFLOW_HOST=pi` so global settings stay under Pi's own agent directory. If Pi cannot expose that root, use `balanced` for the current session and report `--set-verbosity`/`--settings` unavailable instead of pretending persistence. In the FirstMate topology the invoking Pi Captain passes this already-resolved level to `start_main`; Main passes it to every child spawn. `quiet` loads stock FirstMate Calm in each new visible process, while `balanced|verbose` do not force Calm. Ordinary non-Kimiflow FirstMate sessions retain their own `/calm` preference. Claude hosts set `RV` = `${CLAUDE_PLUGIN_ROOT:-$CLAUDE_SKILL_DIR}/hooks/resolve-verbosity.sh`; Codex uses `$KIMIFLOW_PLUGIN_ROOT/hooks/resolve-verbosity.sh`. Map any `--quiet`/`--verbose` to a level; `RV get [--flag <level>]` → the level that governs output immediately, including an empty-session launcher. Unset configuration resolves to `balanced` without a first-run dialog; customization is explicit through launcher/settings.
0.1. **Launcher routing (before slugging a normal run).** If the invocation is empty (`/kimiflow` / `$kimiflow` / `@kimiflow`), `--launcher`, `--menu`, or a vague explicit Kimiflow request without an actionable target, run `${CLAUDE_PLUGIN_ROOT:-$CLAUDE_SKILL_DIR}/hooks/launcher-status.sh --pretty` (Codex: `KIMIFLOW_HOST=codex` and `KIMIFLOW_PLUGIN_ROOT`) and show the compact launcher menu from reference.md "Launcher mode" (one `.launcher.primary_action` + the compact status groups; `.launcher.maintenance.visible_reasons` front-door, `hidden_internal_reasons` drilldown-only). If resolved verbosity is `quiet`, show only the menu/status lines and one blocking question; no preamble, rationale, JSON summary, "I will" narration, or follow-up explanation. User picks a mode → route into it and continue Phase 0; "existing feature check" → `--verify-feature`; a backlog run → resume safety check before Phase 5; headless/no answer → STOP with the snapshot summary and do not auto-pick.
0.25. **Top-model preflight (before slugging a normal run).** Prefer the host's `top` model for orchestration and planning. When the host exposes model identity, verify it now: current Codex → `gpt-5.6-sol`; Claude → strongest available selected tier. A lower-tier session records a quality fallback and continues without asking the user to switch; use bounded top-tier review/verification seats when available, but never pretend they changed the active orchestrator. If model identity is unavailable, preserve the user's selected session and never intentionally downgrade orchestration. → reference.md "Model routing (per-role)".
0.5. **Git check + workspace inventory (first, before product clarification).** Reuse the successful bootstrap `workspace-preflight.sh route` receipt when it already selected this exact root as `direct`; that route computed the same inventory, so do not immediately call `status --pretty` again. Otherwise first run `git rev-parse --is-inside-work-tree`. No repo → skip the Git-only preflight, report it, and ask once whether to `git init` or run through verification only (phases 5–6, no commit). In a Git repo without a reusable clean direct-route receipt—or with a managed/queued/ambiguous route—run `${CLAUDE_PLUGIN_ROOT:-$CLAUDE_SKILL_DIR}/hooks/workspace-preflight.sh status --pretty`, then show one plain summary: current root/branch/HEAD + dirty paths, worktree count, and each extra tree's dirty/ignored/locked/prunable/active/Kimiflow-owned/Codex-managed state. `prune --write` is allowed only for unregistered stale Git metadata; registered prunable metadata is unresolved. Never force remove, delete a branch, stash/reset/clean, or stage/commit foreign paths. Codex-managed trees are app-owned: report them, never alter them directly. Record only genuine foreign/manual cleanup ambiguity for step 3.55; a busy or dirty primary is routed mechanically after slugging and needs no user decision. → reference.md "Workspace preflight".
1. **Slug + autonomous workspace route.** Derive a kebab-case `<slug>`. A FirstMate Kimiflow Main already runs in its durable control worktree; keep that root for its run state and delegate every product write to Main-owned Ships against the supervised project. An ordinary FirstMate child already runs in its assigned product worktree; keep that root and do not create or manage another worktree. Otherwise, before creating run state for a normal write run, call `${CLAUDE_PLUGIN_ROOT:-$CLAUDE_SKILL_DIR}/hooks/workspace-preflight.sh route --run .kimiflow/<slug> --write --pretty` (Codex: `$KIMIFLOW_PLUGIN_ROOT/hooks/workspace-preflight.sh`). Clean/free primary returns `direct` with zero branch/Fleet-state overhead. Busy or dirty primary reserves one of at most three identity-locked `codex/<slug>*` Fleet worktrees and returns its root; change the working directory to that root before continuing. Later runs return FIFO `queued`: wait/retry `route` autonomously when a Fleet slot retires, never ask the user to approve another attempt. Existing foreign/manual/Codex trees are inventory and ambiguity inputs only and are never claimed or mutated. If the same run already owns primary, keep it there even when dirty. Fleet declarations use exclusive Primary/worktree path-contract leases, report `blocked_by`, and require `revalidate` after Primary advances; unresolved drift is durable `needs-reconcile`. State lives under `.kimiflow/<slug>/` at the selected root — in plugin mode, creating `.kimiflow/` there also activates the `commit-secret-gate` hook for the repo (skill-only use loads no hook → reference.md "Commit hygiene").
2. **Mode routing — feature, fix, audit, feature-check, release, or natural alias.** First normalize a leading natural alias (`full|grill|plan|build|quick|review|audit|fix|release`) per the Modes table above (`full` = scope=`large`, not an approval trigger; `grill` stops after Phase 1; `plan` ≙ `--prepare`; `build` implements an approved prepared plan only; `release` enters the explicit Project Release Profile path and does not become a normal feature run). Then detect unresolved requests: build/add/change → feature; crashes/error/bug/wrong behavior → fix; remove dead code / over-engineering / "clean up" / "entschlacken" → **audit** (requires a target path — ask for one if missing); "already built" / "verify feature" / wiring checks → **feature-check** (requires a feature name/path or current diff — ask if missing). `--fix` / `--audit <path>` / `--verify-feature <feature-or-path>` still force the mode. In doubt, ask one simple question. Record mode, alias, and target in STATE. Fix mode branches phases 1–2 (`PROBLEM.md` ≙ `INTENT.md`, `DIAGNOSIS.md` ≙ `RESEARCH.md`) and uses the same versioned material-decision boundary. **Audit mode** branches phases 1–7 (→ reference.md "Audit mode"; always scope ≥ `small`). **Feature-check/review mode** is read-only (→ reference.md "Existing feature check"); it never enters Phase 5 unless the user selects a confirmed finding to fix as a new run. **Release mode** follows reference.md "Project Release Profile" and authorizes exactly one bound profile run.
2.5. **All product-code changes use the normal contracted path.** Audit and release remain lean parent modes. If an approved code-changing audit slice will modify tracked product code/config, materialize exactly that slice as one normal schema-5 `feature|fix` contracted child run, complete its verified atomic commit, then resume the audit parent. If release discovery/audit exposes a required product-code/config repair, create the same bounded contracted child run and resume release only after it completes. Never implement those changes directly inside an uncontracted audit/release parent; pure read-only audit work and profile-bound release metadata/effects keep their existing mode.
3. **Resume check.** With `--resume <slug>`: read its `STATE.md`, resume at the first unfinished phase. Else if `.kimiflow/<slug>/STATE.md` exists → continue. Otherwise initialize it exactly once with `hooks/active-run.sh init-state --run .kimiflow/<slug> --mode <feature|fix|audit|full> --scope <trivial|small|large> --language <BCP-47> --title <one-line feature/problem/target> --write` (Codex: `$KIMIFLOW_PLUGIN_ROOT/hooks/active-run.sh`). Call the initializer alone and retain its literal returned `next_command`; never chain it with `start` or guess the normalized mode/scope. Execute that command immediately for fixes/audits and trivial work. For a fresh non-trivial Contract-4 feature, execute it only at the Phase-4 final-confirmation boundary after PLAN exists. This is the only fresh-state creation path: do not synthesize `STATE.md` or start placeholders; use the command's returned mode/scope (`full` deterministically becomes feature/large). The initializer creates `Flow schema: 5`, feature/problem/target, slug, date, mode, scope, exactly one `Interaction language: <BCP-47>`, discovery plus required `Intent contract: 4`, `Architecture contract: 1`, conformance/convergence and `Execution contract: 1` selectors, the empty `Affected files:` header, active/recovery/frontend selectors, and Phase 0..7. Add one repo-relative affected-file bullet per path once known and `Build risk: none|required` after Phase 2. Phase 2 resolves architecture deliberation to `off|active`; existing Contract-3 and schema-4-and-older runs stay resumable under their pinned gate shape. Affected files are mandatory from Phase 3 and feed plan/staleness/frontend/conformance gates. Backlog means 0–4 done/5 open after a Phase-4 park; an earlier stop stays active. Runs without `Flow schema` predate versioned state; schemas 2–3 keep their prior resumable contracts.
   For schema-5 non-trivial runs, after the initial STATE exists run `hooks/adaptive-control.sh classify --run .kimiflow/<slug> --write`. Use its scope when starting the Active Run; it may conservatively elevate but never downgrade the stated scope. This provisional pass makes no model/network call and Phase 1 repeats it after confirmed Intent.
3.5. **Active session lock.** Fixes, audits, trivial work, and compatible existing runs start immediately. Fresh non-trivial schema-5 `feature|fix` requires `Conformance contract: 1` and `Convergence contract: 1`; features also require `Intent contract: 4`. A fresh non-trivial Contract-4 feature stays read-only through Phase 3, then executes the initializer's retained exact `active-run.sh start ... --write` command immediately before registering its one Phase-4 final confirmation. Start pins mode, scope, current unchanged HEAD, Intent, conformance, convergence, and execution selectors; Phase 5 remains mechanically locked until the confirmed intent lock exists. Create the Active-Run item only after that receipt with `active-run.sh append-item --title "<title>" --kind feature --write`; it takes no `--run`. Execution Contract 1 initializes one private bounded `EXECUTION-TRACE.json`; `status` and `next-action` only read it. Its owner Stop hook records one run-wide observation and selects recovery after two unchanged units without asking. Phase reads still begin at Phase 0 and use `active-run.sh phase-read --run .kimiflow/<slug> --phase <N> --file phases/<phase-file> --packet --write`; fresh unstarted Contract-4 features may record reads through Phase 4, while active legacy runs keep their pinned earlier lock boundary. Never call `clarify-gate`, `plan-blocker-gate`, or `finish --write` before their required phase reads are fresh. Other sessions use the broker route before writes; shared-checkout legacy sessions require `conflict-check`. Terminal `abort|park|fail --reason ... --write` commands are always valid escape paths, including while intake is pending.
3.51. **Codex hook health.** Immediately before the one fresh Phase-4 intake wait (or each pending schema-2 compatibility wait), run `hook-health --require --pretty`; its current-task, plugin-version-bound observation binds exactly that wait. Missing/untrusted CLOSED stops before displaying the question and requests `/hooks` once; a consumed observation never triggers the same question again in that turn.
3.55. **Workspace disposition (still before product clarification).** The broker already resolves ordinary dirty/busy-primary concurrency without a prompt. Use `await-user --kind workspace` at most once only when the user must choose the fate of ambiguous foreign/manual bytes; never ask merely to create, queue, retry, integrate, or retire the owned broker tree. Preserve uncertain provenance untouched. Legacy `remove --write` keeps its strict registered/noncurrent/terminal/clean/unlocked contract; broker retirement additionally accepts only ignored `.kimiflow/` state and requires its green integrated commit receipt plus ancestry before unlock/archive. Finally run exactly `hooks/working-tree-gate.sh --root <selected-root> --pretty` and require OPEN, or use a verified current-run-only dirty set for an already active run. `active-run.sh status` takes no `--run`; use `active-run.sh phase-read-status --run .kimiflow/<slug>` for the phase ledger. Do not probe helper `--help` during the run. If a user-authorized disposition advanced HEAD, run `active-run.sh refresh-baseline --workspace-disposition --write`. Explicitly authorized current-run paths may later be verified and atomically committed by name.
3.6. **Frontend selector (write runs only, no design payload).** New `feature|fix|audit` runs add exactly: `Frontend quality contract: 1`, `Frontend quality: off`, `Frontend quality routing: provisional`, `Frontend quality evidence: pending`, `Frontend quality basis: pending`, `Frontend quality start: pending`, `Frontend quality recovery: clean`, `Frontend quality recovery owns global: no`; keep global `Recovery: clean`. Only after step 3.55 has resolved workspace disposition and the working-tree gate, run `${CLAUDE_PLUGIN_ROOT:-$CLAUDE_SKILL_DIR}/hooks/frontend-quality-gate.sh .kimiflow/<slug> --record-start --write` (Codex: `$KIMIFLOW_PLUGIN_ROOT/hooks/frontend-quality-gate.sh`) and require OPEN. It records the clean post-disposition frontend baseline/contract marker while preserving the Active-Run `started_head` as the original Phase-7 review base; it does not read a design reference. Read-only feature-check/review sets none of these fields.
4. **Phase task-list (glance widget).** Create one task per phase you will actually run (`TaskCreate`), scaled to scope (trivial → the few steps it runs; small/large → the phases of its loop). As you enter a phase set it `in_progress` (`TaskUpdate`) and `completed` when it closes. It **complements** STATE.md (durable/resume) and the colored markers (per-phase event line) and replaces narrated status — it does not change the engine. Subagents keep their OWN internal task-lists; do not mix them into the phase list.
5. **Git context assertion.** Reuse the step-0.5 result; re-run `git rev-parse --is-inside-work-tree` only if the working directory changed. Workspace preflight and local atomic commits require Git.
6. **Scope-gate — hard rule (the default protects simplicity-first):**
   - **Default = `small`** — `large` multiplies subagent/round (token) cost, so it's the exception, not a reflex. Bump to `large` only if ≥~5 files · new dependency or data migration · auth/security/money/privacy path · subtle/hard-to-reproduce bug · user asks for the full loop or uses the `full` alias. A run set to `large` includes the expected run ensemble in its one-line scope announcement (≈ up to N subagents across phases 2–7).
   - **`trivial`** = 1–2 files, no risk, and the user's requested output is exact enough that no user-visible behavior can be misread (fix: obvious cause, e.g. a typo).
   - In doubt, the smaller tier. Effect: trivial → no loop or intent round when exact. small → compact feature intent or direct fix diagnosis, adaptive discovery, 1 plan reviewer, sequential implementation, Phase-7 review ensemble. large / `full` → deeper understanding, strict plan-gate, risk-based decisions only, and the hard test-gate (written in Phase 7 from the Phase-6 command; → reference.md "Hard test-gate").
7. **Display verbosity / utility flags** (after launcher routing, before normal-run work; full rules → reference.md "Display verbosity").
   - **(a)** Reuse the `RV get [--flag <level>]` result from step 0; it already governs output.
   - **(b)** A normal actionable run never pauses for verbosity onboarding. Unset configuration uses `balanced`; surface customization later through the launcher/settings without interrupting the build.
   - **(c)** Explicit utility flags still act directly: `--set-verbosity <level>` → `RV set project`; `--settings` (dialog) → `RV set <scope>`. Write, report path, exit.
8. **Project Map Bootstrap / status check** (recommended, never a prerequisite; full rules → reference.md "Project Map Bootstrap"). `PMS` = `${CLAUDE_PLUGIN_ROOT:-$CLAUDE_SKILL_DIR}/hooks/project-map-status.sh`. `--project-map quick` → create/update `.kimiflow/project/`, report paths, then STOP; `--project-map skip` → record `project_map: skipped` in `STATE.md` and continue. For fresh Contract-4 schema 2, defer the default map existence/status check and its STATE marker until after the final `confirmed` receipt; it is not needed to draft intake. Otherwise, on non-trivial actionable runs: no `.kimiflow/project/INDEX.json` → record `project_map: skipped` and continue without asking; else run `PMS status`, record the result, and once likely affected paths are known run `PMS coverage --affected <path>...` and use its `phase2_depth=compressed|targeted|full` recommendation. Refresh a stale affected section automatically when the bounded local refresh is safe; otherwise record the gap and continue with direct code evidence, never a map-choice prompt. Explicit standalone map/doc/improve runs may still ask their material focus/storage question from reference.md (headless default `codebase+architecture` + `kimiflow` storage; repo-docs storage writes only publish-safe documentation from verified map facts).
