# Kimiflow for Codex

Read installed `SKILL.md` at the plugin root once and follow its lean default loop. Do not preload `reference.md`, the phase files or legacy instructions.

The plugin root is two levels above this installed `skills/kimiflow/SKILL.md`. Use that absolute path for every helper, never the current project's `hooks/` directory. For example:

```bash
KIMIFLOW_HOST=codex /absolute/plugin/root/hooks/check-change.sh --root /absolute/project --check '["npm","test"]'
```

`$kimiflow`, `@kimiflow`, and plain `kimiflow full|grill|plan|build|quick|review|audit|fix|release` select the canonical modes. An empty invocation uses installed `hooks/launcher-status.sh`. `--resume <slug>`, `--project-map <quick|skip>` and `--verify-feature <feature-or-path>` follow the canonical entry and optional-tool rules.

Use Codex's existing plan, worktree, tools and context continuation. Inherit the user's selected model and effort for ordinary work and workers. This applies equally to Astra and local model adapters; there is no pinned cheaper implementer or automatic external Claude call. Pass bounded self-contained context only when independent work warrants delegation.

For an unfinished legacy `Flow schema` run, a managed FirstMate crew or the optional headless controller, load `references/legacy-workflow.md` and `references/legacy-codex.md` instead. Their pinned state and mechanical gates remain authoritative for that run. Do not apply legacy phase, memory, model-calibration or approval requirements to fresh lean work.

Reply in the user's language. State actual checks and results, and preserve task authorization across turns.
